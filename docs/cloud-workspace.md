# 프로젝트 파일과 대화가 연결된 작업실

홈 화면에서 프로젝트 파일, 문서, 에이전트 대화를 함께 사용합니다.
기존 대화 링크도 홈에서 열리며, 이전 대화의 문서를 현재 프로젝트로
가져올 수 있습니다. 기존 대화 데이터와 브라우저 초안은 삭제하지 않습니다.

## 문서 작성과 검토

1. 프로젝트를 만들고 Markdown/TXT/HTML 파일을 가져오거나 새 문서를 만듭니다.
2. 가운데에서 읽거나 편집하고, 오른쪽 대화에서 프로젝트에 대해 질문합니다.
3. 문장을 선택하면 그 부분만 교정할 수 있습니다. 여러 문서에 관한 요청도
   할 수 있으며, 수정안은 파일별로 검토합니다.
4. **승인**한 변경만 서버의 원본 파일에 저장됩니다. 거절은 원본을 바꾸지
   않습니다. 원본이 이미 바뀌었다면 최신 내용과 비교한 뒤 다시 요청합니다.
5. **출처**에서 참고 글을 연결하고, **이력**에서 저장 전 내용을 확인합니다.

수정안의 **본문에서 보기**를 누르면 해당 위치로 이동하고 본문과 카드에 같은
변경 번호가 표시됩니다. 읽기에서는 해당 문단을, Markdown 편집에서는 변경
범위를 강조합니다. 읽기 화면에 나타나지 않는 링크 정의 등은 Markdown 원문에서
보여 줍니다. 작은 화면에서는 검토 패널을 접어 본문을 보여 주며, 하단의
**수정안 보기**로 돌아가거나 **본문 강조 해제** 버튼으로 표시를 지울 수 있습니다.

**나란히 비교**를 누르면 문서 전체를 넓은 화면에서 함께 볼 수 있습니다.

- **검토**에서는 왼쪽에 제안 당시 원본, 오른쪽에 전체 수정안을 표시합니다.
  비교 화면 안에서도 변경별 또는 전체 승인·거절을 할 수 있습니다.
  일부 변경을 승인하거나 거절해도 비교 내용은 최초 제안 그대로 유지되며,
  처리 결과는 검토 목록에 표시됩니다.
- **이력**에서는 선택한 이전 버전을 현재 문서와 비교합니다. 현재 문서에는
  아직 저장하지 않은 편집도 포함됩니다. 비교만으로 복원하거나 저장하지 않습니다.
- Markdown은 서식을 유지하면서 변경된 문단을 강조하고, HTML은 실제 화면을
  각각 표시합니다. **원문 비교**에서는 링크 주소나 서식 변경까지 확인할 수 있습니다.
- 작은 화면에서는 두 버전을 위아래로 표시합니다. **닫기** 또는 `Esc`로
  비교를 끝내고 원래 검토 화면으로 돌아갑니다.

직접 편집한 내용도 저장할 때 버전을 확인합니다. 저장하지 않은 편집은
브라우저 복구본에 보관합니다. 대화와 작업 상태는 서버에 보관하므로
새로고침 후 완료된 수정안을 다시 확인할 수 있습니다. 연결이 중단된
에이전트 작업은 실패 상태로 표시되며 다시 요청할 수 있습니다.

기본 모델은 `global.anthropic.claude-opus-5-5`입니다. 에이전트는 프로젝트
파일을 읽고 검색하며 수정안을 생성합니다. 임의의 셸 명령 실행이나 원본
파일 직접 덮어쓰기 도구는 제공하지 않습니다.

## 소스로 HTML 페이지 만들기

1. 프로젝트에 참고 파일을 가져오고 **출처**에서 필요한 원문과 발췌를 추가합니다.
2. 대화 입력 아래 **작성 방식 → HTML 페이지 만들기**를 선택하고 원하는 페이지를
   설명합니다. 사용할 파일 이름과 자료를 요청에 적어 범위를 지정할 수 있습니다.
3. 에이전트가 제안한 `.html` 파일을 **검토**에서 엽니다. 승인하기 전에도 가운데
   미리보기에서 페이지를 확인할 수 있습니다.
4. 승인 후 미리보기의 문단·카드·표를 클릭해 수정할 영역을 선택합니다.
   영역 목록으로 키보드 선택을 하거나 **상위 영역 선택**으로 범위를 넓힐 수 있습니다.
5. 선택한 영역에 대해 대화로 문구나 디자인 수정을 요청합니다. 검토 패널에서
   **나란히 비교**로 두 화면을 동시에 보거나 **수정 전 / 수정 후**를 전환하고,
   HTML 변경 내용을 펼쳐 확인한 뒤 승인합니다.
6. **HTML 코드**에서 직접 편집하거나 **HTML 다운로드**로 독립 파일을 저장합니다.

HTML 수정안은 내용과 스타일을 한 묶음으로 승인합니다. 요청 이후 원본이
바뀌었거나 선택 범위가 달라지면 최신 문서를 기준으로 다시 요청해야 합니다.
영역에 연결된 출처는 **출처** 패널에서 확인할 수 있고, **인용 넣기**로
해당 영역에 근거와 링크를 추가할 수 있습니다.

현재 지원 범위는 정적인 HTML과 인라인 CSS입니다. 미리보기는 격리된 프레임에서
표시하며 생성된 JavaScript, 외부 스타일시트, 외부 리소스 요청과 페이지 이동을
허용하지 않습니다. 새 요소를 소스 편집으로 추가했다면 저장한 뒤 영역을 선택하세요.
문서에 저장된 `data-oc-id`는 영역 식별에, `data-source-ids`는 출처 연결에 사용합니다.
다운로드에는 미리보기의 선택 표시나 실행용 스크립트가 포함되지 않습니다.

## 기존 파일과 로컬 도구

**브라우저 초안 가져오기**는 이전 작업실의 IndexedDB 문서를 프로젝트로
복사합니다. 사용자가 실행하기 전에는 기존 초안을 서버에 올리지 않으며,
가져온 뒤에도 기존 보관본을 남깁니다.

**내 폴더 연결**로 Claude Code나 Codex에서 사용하는 폴더를 연결할 수
있습니다. 지원 브라우저에서 폴더 접근 권한을 허용해야 합니다.

- 탭이 보일 때 주기적으로, 다시 포커스를 받았을 때 변경을 확인합니다.
- 로컬만 바뀌었거나 서버만 바뀐 파일은 안전한 변경 일괄 반영으로 동기화합니다.
- 양쪽이 모두 바뀐 파일은 비교한 뒤 반영 방향을 선택합니다.
- 파일 삭제는 자동 전파하지 않습니다. 복원이 필요하면 명시적으로 선택합니다.
- 브라우저가 닫히면 로컬 폴더 감시도 멈춥니다. 항상 실행되는 PC 동기화
  프로그램을 설치하는 방식은 아닙니다.

원본 BOM, CRLF/LF, 한글과 이모지를 보존합니다. 문서는 UTF-8 `.md`,
`.markdown`, `.txt`, `.html`, `.htm`, 파일당 2MB 및 200,000자, 프로젝트당 200개,
하위 경로 8단계까지 지원합니다.

## 구현 구조

- 웹/API: 기존 Next.js·FastAPI Fargate 서비스와 ALB/Cognito 로그인.
- 파일: API와 AgentCore가 같은 S3 Files 파일시스템을 마운트합니다.
  편집 직후의 읽기는 S3 객체 동기화를 기다리지 않습니다.
- 에이전트: AgentCore Runtime의 별도 실행 역할로 원본을 읽습니다.
  `s3files:ClientWrite`와 S3 객체 쓰기는 명시적으로 거부합니다.
- 원본 변경: API가 사용자 승인 또는 직접 저장 요청을 처리합니다.
  파일 잠금, 버전 비교, 원자적 교체, 승인 복구 기록을 사용합니다.
- 사용자 구분: ALB 서명을 검증한 Cognito subject로 프로젝트 경로를 결정합니다.
  클라이언트가 보낸 소유자 헤더는 사용하지 않습니다.
- 기록: 전용 DynamoDB 테이블에 프로젝트·대화·작업·수정안 요약을 보관합니다.
  기존 범용 저장 API와 테이블을 공유하지 않습니다.

## 로컬 개발

백엔드 환경에 아래 값을 설정합니다. `WORKSPACE_ROOT`는 쓰기 가능한
절대 경로로 바꾸세요. 운영 배포는 인증 모드와 마운트를 별도로 설정합니다.

```bash
export WORKSPACE_AUTH_MODE=local
export WORKSPACE_METADATA=file
export WORKSPACE_STORAGE_MODE=local
export WORKSPACE_ROOT=/tmp/open-canvas-workspaces
export STORAGE_TYPE=memory
cd apps/backend
.venv/bin/uvicorn main:app --host 127.0.0.1 --port 9000
```

로컬 모드는 `ALB_SIGNER_ARN` 또는 `COGNITO_DOMAIN`이 설정된 인증 환경에서
활성화할 수 없습니다. `AGENTCORE_RUNTIME_ARN`을 지정하지 않으면 같은
읽기 전용 에이전트를 로컬에서 실행하며, 모델 호출에는 로컬 AWS 인증이
필요합니다. 프런트엔드는 기본 내부 API 주소 `http://localhost:9000`을
사용하며 `API_URL`로 변경할 수 있습니다.

검증과 배포 구성은 [AgentCore 배포 기록](../deploy/agentcore/README.md),
API 계약은 [설계 문서](./superpowers/specs/2026-10-25-agentcore-workspace-design.md)를
참고하세요.
