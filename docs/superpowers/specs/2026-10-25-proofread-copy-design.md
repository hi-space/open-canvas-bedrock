# 전체 교정본 저장과 비교

사용자가 2026-10-25에 승인한 흐름을 구현한다.

- 검토 화면에서 **전체 교정본 저장**을 누르면 원본을 보존하면서 화면의
  전체 수정안을 `문서.교정본-날짜.md` 형태의 프로젝트 파일로 저장한다.
- 일부 변경을 승인하거나 거절했어도 저장 대상은 최초의 전체 수정안이다.
  저장 버튼 옆에서 이 동작을 설명한다. 기존 부분 승인 기능을 유지한다.
- 교정 당시 원문과 저장한 교정문을 함께 보관하여 새로고침이나 후속 편집
  이후에도 정확히 두 버전을 비교할 수 있다.
- 이미 생성된 수정안을 사용하므로 저장을 위해 AI를 다시 호출하지 않는다.

## 구현 결정

- 현재 홈인 클라우드 작업실의 기존 문서 수정안에 적용한다. 새 문서 제안은
  기존 승인 흐름으로 저장한다.
- 서버가 보관한 수정안으로 복사본을 만든다. 원본에 대한 승인 상태와
  원본의 현재 내용은 변경하지 않는다. 원본이 이후 편집된 경우에도
  제안 당시의 교정본을 보관할 수 있다.
- 파일 이름에는 UTC 저장 시각과 수정안 ID 일부를 포함한다. 기존 파일을
  덮어쓰지 않는다. 긴 한글 이름은 UTF-8 경계에서 줄이고, 원본 폴더 안에
  유효한 이름을 만들 공간이 없으면 프로젝트 최상위에 저장한다.
- 수정안마다 복사본 하나를 연결한다. 재시도와 중복 클릭은 기존 복사본을
  반환하며 이후 사용자가 편집한 복사본을 덮어쓰지 않는다.
- `.canvas` 안에 원문·교정문·원본 경로·복사본 경로·시각·수정안 ID를 기록한다.
  이 비교 기록은 일반 저장 이력의 최근 30개 제한과 별도로 보존한다.
- 기존 프로젝트 잠금과 승인 복구 저널을 재사용하여 파일 저장 후 메타데이터
  처리가 중단되어도 다음 요청에서 복구한다.
- 저장 후 검토 화면에 파일 경로와 **교정본 열기**를 표시한다. 저장 완료
  응답이 사용자의 파일/프로젝트 이동을 되돌리지 않는다.
- 교정본의 **이력 → 교정 전후 비교**는 저장한 두 스냅샷을 기존
  `DocumentComparison`으로 표시한다. 이후의 일반 저장 이력도 함께 제공한다.
- Markdown/TXT는 BOM·개행·이모지·출처를 그대로 보존하고, HTML은 기존 검증과
  격리 미리보기를 재사용한다. 새 의존성을 추가하지 않는다.

## 완료 기준

실제 API·스토리지 테스트, 프런트엔드 상태·컴포넌트 테스트, 로컬 브라우저
테스트로 원본 보존, 부분 결정 후 전체 저장, 재시도, 재접속 후 비교,
파일 이름 충돌, 저장 중 다른 프로젝트로 이동하는 경우를 검증한다.
