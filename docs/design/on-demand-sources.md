# 필요한 출처만 읽는 작업실

## 목적과 승인된 범위

사용자가 승인한 방향은 출처 보관과 요청별 컨텍스트를 분리하고, 일반 대화와
딥리서치가 필요한 자료를 검색해서 읽도록 바꾸는 것이다. 기존 문서와 인용을
보존하며 출처를 삭제해야 다음 작업을 할 수 있는 문제를 해결한다.

현재 일반 에이전트는 모든 출처 발췌를 최초 메시지에 넣는다. 딥리서치는
프로젝트의 누적 출처 50개 또는 발췌 100,000자에 도달하면 실행 전에 중단한다.
같은 제한이 저장 API, 런타임 입력, 인용 검증에도 사용된다. 단순한 상한 증가는
이 결합을 해결하지 않는다.

## 저장과 조회

- 기존 공유 파일 저장소의 프로젝트 내부 `.canvas/source-library/`에 원문
  발췌를 보관한다. 새 서비스나 런타임 쓰기 권한은 추가하지 않는다.
- 출처 하나의 변경 불가능한 JSON을 내용 해시로 식별한다. 런타임의 현재 출처
  목록에는 ID, 제목, URL, 버전, 발췌 길이와 검색용 단어만 남긴다.
- 작업 접수 시 목록의 버전을 고정한다. 런타임에는 이 목록의 해시만 전달하며
  전체 목록이나 발췌문을 모델 메시지에 넣지 않는다.
- 기존 DynamoDB 인라인 출처는 처음 사용하는 시점에 자동으로 파일에도 기록한다.
  이번 호환 릴리스에서는 인라인 원문을 권위 있는 기록으로 유지한다. 이전 API로
  롤백하거나 구버전 작업이 수정·삭제해도 자료를 잃지 않도록 작업 경계에서 이를
  재확인한다. 파일을 먼저 안전하게 기록한 뒤 메타데이터를 쓰고 ID·URL을 유지한다.
  인라인 원문을 제거하는 저장 스키마 정리는 호환 버전 배포 이후 별도 작업이다.
- 프로젝트에 누적된 출처 개수와 발췌 총량으로 작업 실행을 거부하지 않는다.
  개별 출처의 기존 20,000자 제한과 파일 형식·읽기 크기 검증은 유지한다.
- 출처 제거는 현재 목록에서만 제거한다. 이미 만들어진 작업·수정안이 참조하는
  버전은 유지한다. 자동 삭제나 오래된 출처의 임의 축약은 하지 않는다.

## 일반 대화

모델은 `list_sources`, `search_sources`, `read_source`를 사용한다. 검색 결과는
ID·제목·URL·길이 등 목록 정보이며, 발췌문은 명시적으로 읽었을 때만 전달한다.
검색은 한국어·영어 단어를 지원하는 프로젝트 내부 검색이며 임베딩이나 외부
검색 서비스가 필요하지 않다. 기존 `fetch_reference`도 보관된 자료를 먼저
조회하며 없을 때만 기존 외부 가져오기 경로를 쓴다.

현재 문서에 인용된 URL을 조회 힌트로 제공한다. 문장 교정처럼 원문만 필요한
요청은 출처를 읽지 않고도 끝낼 수 있다.

읽은 근거만 요청별 집합에 넣는다. 한 요청의 근거 예산은 최대 50개, 발췌
100,000자이며 한 번의 `read_source`는 최대 8,000자를 반환한다. 출처가 길면
다음 구간을 읽을 수 있다. 예산 오류는 이번 요청에서 읽는 범위를 줄이도록
안내하며 프로젝트 출처를 지우라고 하지 않는다. 기존 전체 컨텍스트·도구 호출
횟수·시간 제한도 유지한다.

## 딥리서치

리서치 계획의 하위 질문과 후속 질문을 기준으로 보관된 출처를 검색한다.
각 질문과 관련된 출처만 근거 추출에 연결한다. 모든 보관 출처를 모든 질문에
할당하지 않는다.

구현 기본값은 보관 출처 최대 12개, 발췌 합계 32,000자이며 질문별 검색 결과를
번갈아 선택한다. 현재 문서와 사용자가 명시한 URL을 우선한다. 이 예산은
이번 리서치에만 적용되며 웹에서 새로 수집할 근거의 공간을 남긴다.

기존의 출처 중복 URL 처리, 하위 질문별 근거 추출, 후속 웹 검색, 문서 및
HTML·SVG 생성은 유지한다. 최종 인용 제한은 현재 작업에서 사용한 근거에만
적용한다. 새 조사 결과는 프로젝트에 이미 출처가 많아도 저장한다.

## 인용과 버전 일관성

- 런타임이 읽은 출처 ID, 버전, 구간을 결과에 포함한다. API는 작업 시점
  목록에서 그 버전을 확인하고 해당 구간으로 인용 검증용 근거를 재구성한다.
- 모델이 읽지 않은 제목·URL만으로 새 인용을 정당화하지 않는다.
- 수정안에는 실제로 읽은 근거와 버전·구간을 저장한다. 전체 프로젝트 출처를
  매번 복사하지 않는다.
- 기존 본문 인용은 출처 목록에서 제거되었거나 이번에 읽지 않았어도 보존한다.
- 작업 도중 출처를 바꾸거나 제거해도 진행 중인 작업은 고정된 버전을 사용한다.
  완료 처리로 사용자의 최신 출처를 덮어쓰거나 삭제한 출처를 되살리지 않는다.
- 출처 목록과 본문 파일은 소유자·프로젝트 경계 안에서 읽는다. 해시와 실제
  내용의 일치, 경로 및 심볼릭 링크를 검증한다.

## 화면

프로젝트 조회는 출처 요약만 반환하고, **발췌 보기**를 눌렀을 때 본문을
불러온다. 출처 패널은 검색과 나눠 보기를 제공하고 보관 개수를 표시한다.
“문서당 50개”라는 클라우드 프로젝트 제한은 제거한다. 이전 브라우저 전용
문서 편집기의 요청 계약은 그대로 유지한다.

딥리서치 안내는 “발췌문이 있는 모든 출처를 참고” 대신 보관된 출처에서
필요한 자료를 검색한다는 동작을 설명한다.

## 검증과 배포

회귀 검증은 다음을 포함한다.

1. 50개·100,000자를 넘게 보관한 프로젝트의 일반 수정과 추가 리서치 성공.
2. 최초 모델 입력에 보관된 발췌문이 없고, 선택해서 읽은 구간만 후속 입력에
   나타남. 요청이 바뀌면 읽기 예산이 초기화됨.
3. 관련 자료가 목록 끝에 있어도 검색됨. 관련 없는 자료는 근거 추출에서 제외됨.
4. 긴 출처의 중간·마지막 구간 조회, 중복 읽기 및 예산 초과 동작.
5. 기존 자료 자동 이관, 동시 수정·제거, 이전 수정안의 인용 검증 유지.
6. 다른 소유자·프로젝트, 잘못된 해시, 심볼릭 링크 접근 차단.
7. 출처 패널의 필요 시 로딩·오류 재시도와 기존 HTML 수정·다운로드 유지.

설계·구현 기록·검증 결과는 프로젝트 `docs/`에 둔다. 검증 후 기존 GitHub
Actions 경로로 배포하며 운영 출처를 임의로 삭제하거나 재작성하지 않는다.
